Q2: Why PostgreSQL + Prisma ORM instead of MongoDB + Mongoose?
--------------------------------------------------------------------------------
FACULTY INTENT:
Testing database theory: Relational ACID guarantees vs Document store trade-offs.

ANSWER (WHY):
1. Strict Relational Integrity: Our data model is strictly hierarchical and relational:
   Company (1) -> Rounds (N) -> Questions (N) -> QuestionVotes (N).
   In MongoDB, deleting a company requires manual cascading cleanup of orphaned questions
   and votes. In PostgreSQL, Prisma provides native `onDelete: Cascade` enforced by the
   database engine itself.
2. Composite Unique Constraints: A user must only vote ONCE per question (`kind = upvote | matched`),
   and a user must only have ONE coding profile per platform (`userId + platform`).
   PostgreSQL enforces this at the B-tree index level with `@@unique([userId, questionId])`
   and `@@unique([userId, platform])`, making race conditions physically impossible.
3. Type-Safe ORM: Prisma generates TypeScript types directly from the database schema.
   If we change a column in `schema.prisma`, TypeScript compilation fails across all
   controllers immediately, preventing runtime `undefined` errors common in Mongoose.

CODE POINTER:
`server/prisma/schema.prisma` (Lines 58, 69, 94, 146)

Q7: Walk through your authentication flow. How is the token created, passed,
    and verified on protected routes?
--------------------------------------------------------------------------------
FACULTY INTENT:
Testing web security fundamentals: Stateless JWT vs Stateful sessions.

ANSWER (HOW):
1. Registration / Login:
   - User submits email + password.
   - Password is encrypted using `bcrypt.hash(password, 10)` (10 salt rounds).
   - Backend signs a JWT with payload `{ id, email, role, name }` using HMAC-SHA256
     and a server-side secret key (`JWT_SECRET`), valid for 7 days.
2. Client Storage & Interception:
   - Client stores token in `localStorage`.
   - Axios request interceptor attaches it to every outgoing request:
     `Authorization: Bearer <token>`.
3. Middleware Verification (`authenticateJWT`):
   - Express middleware intercepts request, extracts the Bearer header.
   - Calls `jwt.verify(token, JWT_SECRET)`.
   - If valid, attaches payload to `req.user`. If missing/expired, returns `401 Unauthorized`.

CODE POINTER:
- Token signing: `server/src/controllers/authController.ts` (Lines 32-36, 69-73)
- Middleware: `server/src/middlewares/auth.ts` (Lines 13-35)
- Axios interceptor: `client/src/lib/api.ts` (Lines 8-15)

CODE SNIPPET (server/src/middlewares/auth.ts):
```typescript
export const authenticateJWT = (req: AuthRequest, res: Response, next: NextFunction) => {
  const authHeader = req.headers.authorization;
  if (!authHeader || !authHeader.startsWith("Bearer ")) {
    return res.status(401).json({ error: "Access token missing or invalid" });
  }
  const token = authHeader.split(" ")[1];
  try {
    const decoded = jwt.verify(token, JWT_SECRET) as AuthUser;
    req.user = decoded;
    next();
  } catch (err) {
    return res.status(403).json({ error: "Token is expired or invalid" });
  }
};
```

Q11: Explain your Canonical Tag Normalization algorithm. Why is it necessary?
--------------------------------------------------------------------------------
FACULTY INTENT:
Testing data normalization theory and domain design.

ANSWER (WHY & HOW):
Why: Competitive platforms use divergent naming conventions:
- Codeforces uses short strings: `"dp"`, `"graph matchings"`, `"dfs and similar"`, `"data structures"`.
- LeetCode uses kebab-case: `"dynamic-programming"`, `"breadth-first-search"`, `"hash-table"`.
If stored as raw strings, we could never calculate a student's true mastery or match it with
a company's questions.

How:
We engineered a dictionary lookup service (`TAG_TO_TOPIC_SLUG_MAP`) containing 40+ raw tags
mapped to 15 canonical topics. `normalizeTag(tag: string)` trims, lowercases, and performs
an $O(1)$ dictionary lookup. If a tag is unknown, it safely maps to `"arrays-hashing"` or null.

CODE POINTER:
`server/src/services/topicMapping.ts` (Lines 3 - 85)

CODE SNIPPET (server/src/services/topicMapping.ts):

  // Codeforces tags
  "dp": "dynamic-programming",
  "graph matchings": "graphs",
  "dfs and similar": "graphs",
  "data structures": "arrays-hashing",
  "sortings": "arrays-hashing",

  // LeetCode tags
  "array": "arrays-hashing",

  "depth-first-search": "graphs",

Q12: Walk through every single variable and multiplier in the Gap Score formula.
     Show where it is implemented in the codebase.
--------------------------------------------------------------------------------
FACULTY INTENT:
This is the heart of your project's intellectual property. Faculty will test if you
understand the mathematical mechanics.

ANSWER:
Location: `server/src/services/judgeClient.ts` (Lines 256 - 286)

Formula Definition:
For each canonical topic (t) and selected company (C):

```
CompanyWeight = ( companyCount / totalCompanyQuestions ) * 100

StudentCompetency = MIN( ( studentCount / 5 ) * 100,  100 )

GapScore = MAX( 0,  ROUND( CompanyWeight * 1.5 - StudentCompetency * 0.8 ) )
```

Line-by-Line Explanation of Variables:
1. `companyCount`:
   Count of questions in the database for company C tagged with topic t.
2. `totalCompanyQuestions`:
   Total questions logged across all rounds for company C.
   *Protection: `Math.max(companyQuestions.length, 1)` prevents divide-by-zero if a company has 0 questions.*
3. `companyWeight`:
   The percentage frequency of this topic in this company's hiring rounds (0% to 100%).
4. `studentCount`:
   Count of distinct problems solved by this student across LeetCode, Codeforces, and manual entries mapped to topic t.
5. `5 (Competency Divisor)`:
   The baseline campus placement threshold. A student who has solved 5 distinct problems in a canonical topic has demonstrated core algorithmic pattern recognition (100% competency).
6. `1.5 Multiplier (Company Weight)`:
   Gives 50% extra emphasis to what the company actually tests. If a company demands a topic, it dominates the score.
7. `0.8 Multiplier (Student Competency)`:
   Provides credit for the student's solved problems.
8. `MAX(0, ...)`:
   Clamps the score so well-practiced topics never produce negative numbers; they simply drop to 0 ("Balanced / Adequate coverage").

EXACT CODE SNIPPET (server/src/services/judgeClient.ts:L256-L286):
```typescript
const rankedTopics: RankedTopic[] = allTopics.map((topic) => {
  const companyCount = companyTopicCounts[topic.id] || 0;
  const studentCount = studentTopicCounts[topic.id] || 0;

  // Frequency in interview rounds (normalized percentage)
  const companyWeight = (companyCount / totalCompanyQuestions) * 100;

  // Student competency factor (normalized percentage of solved problems or threshold)
  const studentCompetency = Math.min((studentCount / 5) * 100, 100);

  // Gap = High appearance in company, low student solved count
  const gapScore = Math.max(0, Math.round(companyWeight * 1.5 - studentCompetency * 0.8));

  let recommendationNote = "Adequate coverage";
  if (companyCount > 0 && studentCount === 0) {
    recommendationNote = `Frequently asked in rounds (${companyCount} questions), but 0 solved by you`;
  } else if (gapScore > 30) {
    recommendationNote = `High question weight (${companyCount}) with low practice count (${studentCount})`;
  } else if (studentCount > 0) {
    recommendationNote = `Solved ${studentCount} problems; strengthen with advanced patterns`;
  }

  return { topicId: topic.id, topicName: topic.name, companyFrequency: companyCount, studentSolvedCount: studentCount, gapScore, recommendationNote };
});

// Sort descending by gapScore
rankedTopics.sort((a, b) => b.gapScore - a.gapScore || b.companyFrequency - a.companyFrequency);
```

Q16: Explain how you calculate ATS Keyword Overlap. Why do you need stop words?
--------------------------------------------------------------------------------
FACULTY INTENT:
Testing basic Natural Language Processing (NLP) tokenization and set theory.

ANSWER (HOW & WHY):
Why: Common English words ("the", "and", "with", "experience") appear in every job description.
If not removed, a resume would falsely score 90% overlap just from common prepositions!

How:
1. Stop-Words Filter: A Set of 40+ common English stopwords.
2. Tokenization: Converts text to lowercase, replaces non-alphanumeric characters with spaces,
   filters tokens with `length > 2` not in the stop-words set.
3. Set Intersection (Jaccard-like approach):
   - Computes: `matchedKeywords = jdKeywords.filter(kw => resumeWords.has(kw))`
   - Computes: `missingKeywords = jdKeywords.filter(kw => !resumeWords.has(kw))`
   - Formula: `OverlapScore = MIN(100, ROUND( (matchedKeywords.length / totalJDKeywords) * 100 ))`

CODE POINTER:
`server/src/services/aiService.ts` (Lines 27 - 75)

CODE SNIPPET:
```typescript
const stopWords = new Set([
  "the", "and", "a", "an", "to", "in", "for", "with", "of", "at", "by", "from",
  "into", "is", "are", "was", "were", "be", "been", "have", "has", "do", "does",
  "which", "who", "whom", "this", "will", "would", "can", "could", "experience", "role", "work"
]);

const extractKeywords = (str: string) => {
  const words = str
    .toLowerCase()
    .replace(/[^a-z0-9#+.]/g, " ")
    .split(/\s+/)
    .filter((w) => w.length > 2 && !stopWords.has(w));
  return Array.from(new Set(words));
};

const jdKeywords = extractKeywords(jobDescriptionText);
const resumeWords = new Set(extractKeywords(resumeText));

const matchedKeywords = jdKeywords.filter(kw => resumeWords.has(kw));
const missingKeywords = jdKeywords.filter(kw => !resumeWords.has(kw));
const score = Math.min(100, Math.round((matchedKeywords.length / Math.max(jdKeywords.length, 1)) * 100));
```
